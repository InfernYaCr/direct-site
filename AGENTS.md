# AGENTS.md — оркестрация для проекта «direct site»

Какие субагенты и инструменты использовать на каждом этапе. Цель — параллелить
независимую работу и беречь основной контекст.

## Роли по фазам

| Фаза | Агент / инструмент | Зачем |
|---|---|---|
| Анализ референса | Браузерный MCP (Claude in Chrome / Playwright) | Скриншоты секций референса по брейкпоинтам, замеры цветов/отступов |
| Каркас Astro | основной агент | Скаффолд, токены, шрифт — небольшой объём, без делегирования |
| UI-примитивы | `a11y-architect` | Доступные Button/Form/Card: focus, ARIA, reduced-motion |
| Секции (вёрстка) | основной агент + браузерный MCP | Реализация + визуальная сверка со скриншотом секции |
| Сверка дизайна | `code-explorer`/`Explore` (по своему коду), браузерный MCP (визуал) | Найти расхождения с референсом |
| Ревью кода | `typescript-reviewer`, затем `code-reviewer` | После каждой значимой секции/перед коммитом |
| A11y/визуал-аудит | `a11y-architect` | Перед закрытием Фазы 3 |
| Производительность | `performance-optimizer` | Фаза 4: Lighthouse, бюджет JS/CSS, шрифты/картинки |
| Чистка | `refactor-cleaner` | Только по запросу; убрать осиротевший код после правок |

## Когда делегировать subagent

- **Широкий поиск по своему коду (>3 запросов)** → `Explore`/`code-explorer`.
- **Готовый кусок кода написан/изменён** → `typescript-reviewer` (Astro/TS),
  затем `code-reviewer` для общей проверки. Не пропускать перед коммитом секции.
- **Доступность UI-компонента** → `a11y-architect` (проактивно при создании
  Button/LeadForm/интерактивных карточек).
- **Падает сборка/типы** → `build-error-resolver`.
- **Просадка Lighthouse / тяжёлый бандл** → `performance-optimizer`.
- Мелкие правки в одном файле — делать напрямую, без агентов.

## Параллельный запуск

Независимые проверки запускать одним сообщением (параллельно), например после
Фазы 3: `a11y-architect` (доступность) ‖ `performance-optimizer` (CWV) ‖
`typescript-reviewer` (типобезопасность). Не делать это последовательно.

## MCP-инструменты

- **context7** — актуальные доки Astro / View Transitions / Tailwind перед
  использованием незнакомого API. Не для общей логики.
- **Браузерный MCP (Claude in Chrome / `mcp__Claude_Preview__*`)** — ключевой
  для «компоновки блоков как в референсе»:
  1. открыть `https://nkorytin.ru/`, снять скриншоты секций на 375/768/1440;
  2. поднять `npm run dev`, открыть нашу сборку;
  3. визуально сравнить секция-в-секцию, фиксировать расхождения.
- **jcodemunch** — навигация/поиск по своему коду по мере роста проекта
  (символы, ссылки, мёртвый код), вместо широких чтений.
- **Figma Dev Mode MCP** — НЕ требуется: источник дизайна — сам референс,
  отдельного Figma-макета нет.

## Дисциплина контекста

- Делегируешь ресёрч агенту — не дублируй те же поиски сам.
- Результаты больших прогонов (Lighthouse, axe) — просить краткий отчёт
  (вердикт + список фиксов), а не сырой вывод.
- Не читать широко большие сгенерённые файлы Astro-сборки (`dist/`).

## Definition of Done (общий)

Секция/фаза закрыта только когда: `astro check` чист, сборка зелёная, адаптив
проверен, визуальная сверка с референсом сделана, ревью-агент отработал,
коммит атомарный (`feat(<scope>): ...`).
